Control de Versiones

Definición

Un Sistema de Control de Versiones (VCS) es una herramienta de software que registra los cambios realizados sobre un archivo o conjunto de archivos a lo largo del tiempo, permitiendo recuperar versiones específicas, auditar modificaciones y colaborar en equipo sin sobrescribir código.

Tipos de Control de Versiones: Características, Ventajas y Desventajas

1. Locales (LVCS)

Guardan parches de cambios en una base de datos local dentro del mismo equipo (ej. RCS).

  • Ventajas: Rápidos, sin configuración de red.
  • Desventajas: Sin colaboración; pérdida total si falla el disco duro.

2. Centralizados (CVCS)

Un único servidor central almacena los archivos versionados y los clientes se conectan a él (ej. SVN, Perforce).

  • Ventajas: Administración centralizada y control estricto de permisos.
  • Desventajas: Punto único de fallo; si cae el servidor no se puede guardar historial.

3. Distribuidos (DVCS)

Cada desarrollador clona el repositorio completo con todo su historial íntegro (ej. Git, Mercurial).

  • Ventajas: Trabajo offline, copias de seguridad completas en cada cliente y ramas rápidas.
  • Desventajas: Curva de aprendizaje inicial más alta y mayor uso de espacio local.

Funcionamiento, Rastreo y Gestión de Cambios

En Git, los archivos pasan por tres estados: Working Directory (modificados), Staging Area (preparados) y Repository (confirmados con commits). El rastreo se gestiona creando ramas (branches) independientes por cada función y uniéndolas mediante Merge / Pull Requests.

Ejemplo práctico en Git 
git init
git checkout -b feature/login
git add LoginActivity.kt
git commit -m "feat: agrega pantalla de inicio de sesión"
git push origin feature/login

Persistencia y Acceso a Datos

Definición y Características

La persistencia de datos es la capacidad de una aplicación móvil para conservar información de forma permanente más allá del ciclo de vida de la app. Se caracteriza por su durabilidad, integridad, eficiencia de acceso, seguridad y soporte para funcionamiento offline.

Forma de Persistencia Explicación Tipos de Datos Almacenables
Archivos y Preferencias Almacenamiento interno/externo o pares clave-valor (SharedPreferences / UserDefaults). Ajustes de usuario, tokens, archivos JSON, XML, imágenes en caché y logs.
Bases de Datos Locales Motores embebidos en el dispositivo (SQLite, Realm, CoreData). Datos estructurados relacionales, catálogos offline, historiales y listas.
Bases de Datos Remotas Servidores externos consumidos mediante Servicios Web (APIs REST / GraphQL). Información multiusuario en tiempo real, respaldos en la nube y multimedia pesada.

Mecanismos de Control de Acceso y Consumo Web

  • Biblioteca de clases: APIs nativas del SDK (java.io, FileManager) para manipular archivos.
  • Clases de SQLite: Wrappers nativos (SQLiteOpenHelper) para consultas SQL directas.
  • Mapeo Relacional de Objetos (ORM): Librerías (Room, CoreData, Drift) que mapean tablas SQL a objetos del lenguaje.
  • Autenticación y Web Services: Envío de credenciales vía HTTPS, recepción de token JWT / OAuth 2.0, almacenamiento seguro (Keystore/Keychain) y envío en cabecera Authorization: Bearer <token>.
Ejemplo: Petición autenticada a API REST 
fetch('https://api.appmovil.com/datos', {
  method: 'GET',
  headers: { 'Authorization': 'Bearer eyJhbGciOiJIUzI1Ni...' }
}).then(res => res.json()).then(data => console.log(data));

Gestión de Sensores

Definición

Los sensores móviles son componentes de hardware o virtuales que miden magnitudes físicas del entorno o del movimiento del dispositivo y las transforman en datos digitales procesables por la aplicación.

Sensores de Movimiento

  • Acelerómetro: Aceleración en ejes X, Y, Z.
  • Giroscopio: Velocidad de rotación angular.
  • Podómetro: Conteo de pasos.

Sensores de Posición

  • Magnetómetro: Campo magnético (brújula).
  • Proximidad: Cercanía de objetos a la pantalla.
  • GPS / GNSS: Coordenadas geográficas.

Sensores Ambientales

  • Fotómetro: Nivel de luz ambiental (lux).
  • Barómetro: Presión atmosférica / altitud.
  • Termómetro: Temperatura ambiente.

Proceso de Gestión de Sensores

  1. Habilitación: Obtener instancia del gestor (SensorManager / CMMotionManager), comprobar disponibilidad del hardware y solicitar permisos al usuario.
  2. Obtención: Registrar un Listener indicando la tasa de muestreo adecuada para optimizar el consumo energético.
  3. Procesamiento: Filtrar ruido de las lecturas (filtros paso bajo), transformar coordenadas y actualizar la interfaz. Desregistrar el sensor al pausar la pantalla.

Uso de Recursos Multimedia

Definición y Tipos Aplicables

Son los elementos audiovisuales e interactivos integrados en una app móvil para mejorar la comunicación y experiencia de usuario:

  • Imágenes: Mapas de bits (PNG, JPG, WebP) y vectores escalables (SVG, VectorDrawable).
  • Audio: Efectos cortos (WAV, OGG) y pistas de música o streaming (MP3, AAC).
  • Video: Formatos acelerados por hardware como MP4 (H.264/H.265) y WebM.
  • Animaciones y elementos dinámicos: Transiciones de UI, animaciones vectoriales JSON (Lottie) y gráficos 2D/3D (OpenGL ES, Metal, Vulkan).

Estructura en Proyectos

  • Android: res/drawable (imágenes por densidad dpi), res/raw (audio/video) y carpeta assets/.
  • iOS: Catálogo Assets.xcassets (@1x, @2x, @3x) y el Main Bundle.
  • Flutter / React Native: Carpeta assets/ declarada en pubspec.yaml o importada en JS.

Componentes de Software

  • Reproducción: ExoPlayer / Media3 (Android), AVPlayer (iOS).
  • Captura: CameraX, MediaRecorder, AVCaptureSession.
  • Gestión de Memoria: Librerías Glide, Coil, Picasso y SDWebImage para carga asíncrona y caché.

Servicios y Notificaciones

Definición y Tareas en Segundo Plano

Un Servicio ejecuta operaciones de larga duración sin interfaz visual. Las tareas en segundo plano permiten sincronizar datos, subir archivos o procesar información cuando la app está minimizada o cerrada.

Tratamiento de Notificaciones e Implementación

  • Notificaciones Locales vs Push: Las locales se programan dentro del dispositivo; las Push se envían desde un servidor externo mediante pasarelas en la nube.
  • Proveedores de Contenido (Content Providers): Interfaz segura basada en URIs para compartir datos entre aplicaciones (ej. contactos, galería).
  • Implementación de Tareas: Uso de WorkManager (Android) o BackgroundTasks (iOS) para tareas diferidas garantizadas.
  • Implementación de Notificaciones: Solicitud de permisos en tiempo de ejecución, creación de Canales de Notificación y construcción visual mediante NotificationCompat.Builder.

Servicios de Cómputo en la Nube (MBaaS)

  • Firebase (Google): Cloud Messaging (FCM para notificaciones push), Firestore, Auth y Cloud Functions.
  • AWS Amplify: Cognito (usuarios), S3 (archivos), AppSync y SNS (notificaciones).
  • Supabase / Azure Mobile Apps: Bases de datos en tiempo real, almacenamiento y APIs instantáneas.

Librerías y Toolkits para Desarrollo Móvil

¿Qué es una Librería?

Colección de funciones y clases reutilizables que resuelven una necesidad puntual (redes, JSON, imágenes). Tu código invoca a la librería cuando la necesita.

¿Qué es un Toolkit?

Conjunto completo de herramientas de desarrollo, compiladores y componentes visuales (UI Toolkit / SDK) que definen la arquitectura base para construir toda la aplicación.

Librerías Especializadas y Diferenciación de Toolkits

Librerías clave: Retrofit / Alamofire (HTTP), Kotlin Coroutines / RxJava (asincronía), Dagger Hilt / Koin (inyección de dependencias).

Toolkit Lenguaje Diferencia Principal
Jetpack Compose Kotlin UI Toolkit nativo declarativo moderno para Android.
SwiftUI Swift UI Toolkit nativo declarativo para el ecosistema Apple (iOS/iPadOS).
Flutter Dart Toolkit multiplataforma que renderiza sus propios widgets con motor gráfico propio.
React Native JS / TS Framework multiplataforma que compila componentes hacia vistas nativas del sistema.

Depuración y Seguridad

¿Qué es la Depuración?

Proceso de detectar, analizar y corregir fallos lógicos, fugas de memoria o problemas de rendimiento durante la ejecución de la aplicación móvil.

¿Qué es la Seguridad Móvil?

Conjunto de técnicas de protección para resguardar la integridad del código, los datos locales y el tráfico de red contra ataques o ingeniería inversa.

Herramientas de Depuración y Buenas Prácticas de Seguridad

  • Logcat / Consola Xcode: Monitorización en tiempo real de eventos y excepciones del sistema.
  • Breakpoints y Watchers: Pausa controlada de ejecución para inspeccionar variables en memoria.
  • Profilers (CPU, Memoria, Red, Energía): Análisis gráfico de consumo de RAM, batería y tráfico HTTP.
  • Seguridad Aplicada: Ofuscación de código con R8/ProGuard, cifrado local con Android Keystore / iOS Keychain y validación de certificados mediante SSL Pinning.
